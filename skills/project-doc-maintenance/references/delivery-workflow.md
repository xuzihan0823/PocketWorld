# 开发与交付流程

适用的仓库规范决定分工、默认分支、提交格式和审查权限。以下流程在目标项目的任务工作区执行。当前任务的后续调整复用原分支与 PR。

## 开始开发

1. 检查 `git status --short`、`git worktree list` 和远端信息。有 GitHub 远端时查看 `gh pr list`，必要时查看相关 PR，确认任务归属与并行修改。
2. 新任务先 `git fetch origin`，基于最新默认分支建立任务分支。PocketWorld 使用 `origin/main`，分支命名采用 `type/short-description`。一个任务对应一个分支和 PR。
3. 并行任务各用独立 worktree。主检出目录用于同步、创建任务和集成验证。已有未提交修改先确认归属，保留他人的工作。
4. 先核对模块分工、公共接口和相关规范。公共类型、依赖、锁文件、构建配置及跨模块变更按仓库规则由负责人协调。

例如，在确认目录和分支名可用后创建工作区。

```sh
git fetch origin
git worktree add ../pocketworld-short-description -b feat/short-description origin/main
```

## 本地开发与验证

读取当前分支的包管理器、锁文件、运行版本、开发脚本和测试准备步骤。沿用项目既有流程，同机依赖复用和其他机器首次安装按环境分别处理。PocketWorld 的具体方式见 [本地开发流程](pocketworld-local-dev.md)。

验证与改动风险匹配。纯文档检查差异、链接和结构。代码改动执行仓库要求的类型检查、构建及相关回归，交互改动通过实际入口检查。完成验证后及时推进交付，后续修改影响已验证部分时再检查。

## 提交与推送

- 同步相关产品规范、交互契约和模块进度，清理失效内容。单次任务的阶段、下一步和阻塞记录在当前 PR 或仓库已有计划中。
- 使用 `git add -- 文件路径` 明确暂存本任务文件，禁止 `git add -A`。使用 `git --no-pager diff --cached` 审阅实际提交内容，再运行 `git --no-pager diff --cached --check`。
- 排查密钥、令牌、环境文件、个人邮箱、真实服务地址和账户标识，以及依赖、构建产物、日志和本地数据。示例使用占位值，保留合法声明。
- 提交作者邮箱使用当前贡献者自己的 GitHub noreply 地址。PocketWorld 提交格式采用 `type(scope): 中文摘要`，说明修改原因、行为变化和验证范围。
- 首次可审阅提交形成后尽早 `git push -u origin 分支名`，创建草稿 PR。后续以新增提交推送到同一分支，更新同一 PR。
- 禁止直接推送 `main`、擅自强推、改写已共享历史或覆盖其他任务。冲突按模块责任协调，保留双方已授权功能。

## 草稿 PR 与审查

推送后先查询当前分支是否已有 PR。存在时更新原 PR，首次交付使用 `gh pr create --draft --base main --head 分支名 --body-file 说明文件路径`。多行正文写入临时 UTF-8 文件，按仓库 PR 模板填写。

PR 至少说明目标、修改原因、当前完成情况、下一步和剩余事项、跨模块与兼容性影响、相关文档、实际验证结果及未验证项。有界面或玩法变化时按仓库要求提供截图或短录屏，资源或依赖变化说明包体影响。

草稿阶段如实区分计划与完成。验证与交付条件满足后转 Ready for review，按审查意见在原分支补充提交。合并由仓库指定负责人执行，按既有授权处理合并请求与自动合并。

## 合并后及时清理

确认任务内容已合入最新远端默认分支后，及时清理该任务的远端分支、本地分支和 worktree。清理前完成以下检查。

1. 从仍保留的检出目录执行 `git fetch origin`，核对 PR 为已合并，记录 PR 合并时的源分支提交及当前分支提交。
2. 普通合并通过 `git merge-base --is-ancestor 分支名 origin/main` 确认内容已并入。Squash 或 rebase 合并结合 PR 合并状态、合并提交和最终差异确认交付内容，核对源分支在合并后是否新增提交。
3. 本地和远端分支都要核对，检查 worktree 的暂存、未暂存、未跟踪文件及本地数据。存在额外提交、未交付文件、其他任务占用或归属不明确时，保留并说明具体问题。
4. 检查通过后删除已合并的远端任务分支，从其他工作区移除干净的任务 worktree，再用 `git branch -d 分支名` 删除本地分支。清理已失效的 worktree 登记并核对列表。

Squash 或 rebase 合并导致安全删除命令拒绝时，只有在上述内容核对完成且用户已授权清理已合并分支后，才针对确认的分支使用 `git branch -D`。远端删除前再次核对分支头，发现变化先重新确认内容。主分支及其他仍在开发的任务按各自生命周期维护。
