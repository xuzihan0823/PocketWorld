# PocketWorld 适配说明

在目标 PocketWorld 工作区中先检查实际目录和适用规则，再选择以下入口。仓库整理或接口迁移后，以当前调用链定位新位置，并更新受影响的链接。

## 复用已有文档

| 职责 | 查找入口 | 维护方式 |
| --- | --- | --- |
| 协作约定与授权边界 | 根目录 `AGENT.md` 及适用的 `AGENTS.md` | 沿用分工、公共契约维护者和 PR 流程 |
| 产品行为 | 根目录 `SPEC.md`、相关模块设计说明 | 分清确定要求、初始参考方案与当前实现 |
| 公共接口 | `src/types/game.ts`、`interactable.ts`、`world.ts` | 核对定义、真实调用方和实现方 |
| 当前模块能力 | 各模块已有 `进度文档.md` | 整理当前状态、限制和验证证据 |
| 单次任务状态和交付 | 当前任务 PR、`.github/PULL_REQUEST_TEMPLATE.md` | 写目标、进展、集成影响、下一步和验证结果 |
| 跨模块行为约定 | 先搜索已有契约或模块说明 | 初始化时按实际需要补充契约和入口链接 |

项目现有规则采用一个任务一个分支和 PR，公共类型由集成负责人协调。分别核对场景、小游戏及功能模块的最新分工。既有模块进度文件保留其职责，任务状态集中到当前任务 PR。已有 `.planning/` 记录需要先确认任务归属。

开发任务按 [开发与交付流程](delivery-workflow.md) 提交、推送和创建草稿 PR，按 [本地开发流程](pocketworld-local-dev.md) 复用同机依赖、选择端口、预览与验证。任务内容合入 `main` 后及时清理已交付分支和 worktree。

## 技术与数据边界

- 沿用 React、TypeScript、Vite 和当前 Three.js 场景，小游戏沿用现有 Canvas 2D 接入方式。新增依赖与公共配置由负责人协调。
- 交付产物满足当前纯静态部署约束，资源路径使用 Vite 支持的导入或相对路径。
- 持久化核对当前实际存储实现和既有数据，遵守 `pocketworld:` 命名空间及相关迁移要求。
- 保持暂停、静音、退出、按键隔离和资源释放约定。资源数量、包体和运行开销按产品规范及实际改动验证。

具体要求以目标工作区适用的 `AGENT.md`、`SPEC.md` 和当前用户指令为准，初始设计与当前实现的差异按任务明确处理。

## 按任务选用 Three.js 技能

本仓库分发 24 个独立的 `threejs-*` 技能。安装到项目后，在技能目录中按名称查找，加载本次任务直接需要的指导。仅安装项目文档维护技能时，沿用仓库规范和当前依赖的官方资料。

PocketWorld 的 3D 主场景使用 React Three Fiber 与 Drei。涉及场景开发时，优先结合 `threejs-r3f` 核对组件、Canvas、渲染循环和资源生命周期，再按下面的范围选择相关技能。

| 变更范围 | 相关技能 |
| --- | --- |
| 相机、坐标、家具布局与人物动作 | `threejs-scene`、`threejs-geometry`、`threejs-animation` |
| 模型、贴图、材质、灯光与视觉效果 | `threejs-assets`、`threejs-materials`、`threejs-lighting`、`threejs-shaders`、`threejs-postprocessing` |
| 点击、拖动、键盘、音频和 HTML 界面协同 | `threejs-interaction`、`threejs-audio`、`threejs-html`、`threejs-accessibility` |
| 帧率、内存、渲染故障与交付验证 | `threejs-performance`、`threejs-debugging`、`threejs-testing`、`threejs-deployment` |
| 新体验规划或专项能力 | `threejs-web` 及对应的产品展示、物理、粒子、空间数据、WebGPU、XR 技能 |

核对当前依赖及实际调用链，保留项目已选的渲染与交互架构。专项技能中的技术方案按用户需求和项目约束选用，外部服务、依赖变更及发布操作遵循原有授权边界。涉及交互或接口变更时，同时按本技能维护相关规范、契约和 PR。

## 从真实入口识别影响

优先使用 `rg --files` 找文件，再搜索接口或符号。目录迁移时重新查找这些符号及其引用。

- 游戏与电脑接入从 `GameCartridgeProps`、`GameId`、`gameModules`、`MediaObjects` 和 `ComputerScreen` 查起。
- 场景与角色行为从 `WorldAction`、`WorldSceneProps`、`useWorldController` 和 `InteractableItemConfig` 查起。
- 音乐与共享音频从 `roomAudio`、`MusicDisc` 和当前媒体入口查起。
- 日程和书柜从当前功能目录、公共 adapter 类型、持久化实现及相关测试查起。

例如，游戏接入需要从 `src/main.tsx` 和 `src/App.tsx` 追踪当前入口，再检查场景中的卡带加载器及两款游戏默认导出。仓库中可能同时保留旧组件或迁移中的文件，沿应用调用链确认当前使用情况。

## 游戏与电脑交互的适配示例

创建或更新这份契约时，集成负责人协调电脑外层，两款游戏维护者确认自身实现。公共签名链接到 `GameCartridgeProps`，具体行为结合当前源码和测试核对。

| 需要记录的约定 | 核对点 |
| --- | --- |
| 启动和加载 | 卡带交互如何启动按需加载，同时挂载几款游戏，加载失败和迟到结果如何处理 |
| 激活与暂停 | `isActive` 的决定方，失焦、切后台、收起及重新进入时的模拟、输入和音频行为 |
| 静音 | `isMuted` 如何传入，游戏局部静音与房间音频之间的关系 |
| 按键隔离 | 游戏占用的 `Esc`、方向键、空格和其他快捷键如何与房间协调 |
| 成绩与存储 | 成绩回调的发起方、消费方、存储命名空间和既有数据兼容 |
| 退出与卸载 | 游戏内返回、`onExit`、拔卡和离开电脑的区别，状态保留及资源清理责任 |
| 尺寸与显示 | 800 × 600 逻辑布局、实际渲染分辨率和外层缩放的职责 |

验收按本次改动选择独立游戏入口与房间内真实入口，覆盖相关暂停、恢复、静音、重复进入退出和资源清理。浏览器模拟与实体设备验证分别记录。

## 在本项目初始化维护机制

用户要求初始化时，在 `AGENT.md` 中补充文档归属、维护者、更新触发条件和交付要求，链接本次需要的交互契约。在 PR 模板加入已核对文档、接口影响和待协调事项。产品规范继续承载用户行为要求，类型定义继续承载代码签名。

文档与行为冲突需要具体说明。例如 `SPEC.md` 的初始玩法或旧界面流程，与当前游戏和卡带交互可能存在差异。结合用户已确认要求和当前任务处理差异，保留待确认事项及验证边界。

纯技能包维护按文档范围验证。宿主能力、安装位置和实际调用另行检查，发布到源码仓库与在目标项目安装分别记录。
