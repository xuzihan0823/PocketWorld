# Luna 骨架精修与抱兔交互任务方案

目标是把现有骨架初版修整为能稳定制作动画的角色资产，并完成一次“拿起兔子、抱住、放下”的完整交互。先解决模型与权重问题，再接入 PocketWorld；后续坐卧、翻书和裙摆动态建立在这套资产之上。

## 当前基础与范围

以 [PR #21](https://github.com/xuzihan0823/PocketWorld/pull/21) 的交付资产为起点。该 PR 尚未合并；其中人物有 87 根骨骼，包括双手各五条三节指链，兔子已独立。结构检查和有限姿势检查通过，但完整握拳、抬臂、坐卧及游戏内交互尚未验收。左手、部分衣服及兔子遮挡区域经过补建，需要优先检查表面连续性。

第一批完成模型精修和 Blender 抱兔示范，第二批完成游戏内交互，第三批再扩展坐卧、阅读及裙摆动态。

当前已在 PR #23 同步最新主分支和 PR #21 初版资产，隔离重建脚本的输出目录。
兔子按用户提供的五视角参考图重新建模，交付精修 `.blend`、独立 GLB、握持标记和五视角预览。
模型结构与重新导入检查通过，详见 `art/resident/README.md`。
人物抬臂检查暴露出肩部补面与权重问题，人物精修及后续动作仍在进行。

## 第一阶段 固定资产版本和制作流程

保留原始 `luna.glb` 与 PR #21 初版，另建精修版本，记录输入资产哈希、Blender 版本和导出配置。明确 `.blend` 是人工精修的主文件，GLB 是从它导出的运行时资源。

现有 `build_luna_rig.py` 会重写交付路径。精修前先将重建输出与人工精修文件分开，避免重跑脚本覆盖权重绘制、补面或新动画。脚本承担可复现的基础处理与检查，手工调整保存在版本化 `.blend` 中。

交付与验收：原始、初版和精修资产各自可定位，导出来源明确，可恢复到上一版；不覆盖原始模型，不修改其他任务的工作区。

## 第二阶段 修复模型与骨骼权重

优先处理左手腕连接、肩膀及手臂补面、兔子移走后露出的衣服区域，以及兔子的耳根、头背面和围巾连接处。逐处检查正面、背面、侧面和斜视角，修复可见破洞、薄片、尖刺、重叠闪烁及明显材质接缝。

手部按“一根手指、一个关节”检查，调整关节中心、弯曲方向和蒙皮权重。需要增加几何时，优先在关节和缺面处局部补充拓扑，保留现有外观和贴图。衣服与身体之间若存在生成模型留下的几何粘连，先拆开并补齐必要表面，再调整权重；不能只靠缩小动作幅度掩盖拉扯。

以下角度是首轮测试目标，不是所有关节统一套用的限制。如需缩小范围，应说明对应的几何或解剖原因。

| 检查项目 | 测试动作 | 通过标准 |
| --- | --- | --- |
| 单指控制 | 双手十指逐节弯曲，非拇指关节先检查约 30 度和 60 度 | 对应指节可辨认，相邻手指没有非预期运动 |
| 手掌与手腕 | 张手、半握拳、自然握拳、拇指对指，手腕小幅屈伸和旋转 | 掌面与指缝完整，手腕连续，没有明显塌陷或穿透 |
| 肩肘 | 前伸、侧抬至约 90 度，肘部约 90 度弯曲 | 轮廓连续，衣服和头发没有被错误牵动 |
| 髋膝 | 单腿抬起、屈膝、基本坐姿 | 腿部连续，裙摆没有被拉成长片；穿插有明确修复方案 |
| 裙摆与头发 | 单独调整各骨链，再与人体姿势组合 | 控制区域正确，没有漂浮顶点和突变 |
| 独立兔子 | 完整旋转查看，单独移动和缩放 | 不带人物残片，原点适合摆放，修补处没有明显开口 |

保存静置与关键姿势的近景截图及短播放录像，覆盖掌心、手腕和兔子背面。结构检查继续要求权重归一化、每顶点最多四个骨骼影响、无漏绑顶点。不能只凭正面远景或骨骼数量通过验收。

交付：精修 `.blend`、人物与兔子 GLB、姿势检查记录和剩余限制。影响抱兔动作的问题未解决时，先修复，不进入游戏接入。

## 第三阶段 制作完整抱兔示范

第一版让人物站定，兔子放在固定高度的台面上，集中检查手部接触和道具跟随。地面拾取、下蹲和边走边抱留到后续。

动作依次包含准备、伸手接触、手指收拢、拿起、抱持、放回、松手和双手收回。调整肩膀、肘部、手腕与手指之间的先后关系，避免整条手臂同时僵硬转动。

兔子继续作为独立资产，明确主手握持点、另一只手的辅助接触点和放置点。可以在 Blender 中用约束辅助制作，但导出前需烘焙必要的变换，不能假设 Blender 约束会自动在 Three.js 中生效。

同步定义抓取和释放的事件时刻，记录在项目能读取的数据中。Blender 时间线标记只作为制作参考，不能当作 GLB 自带的事件回调。人物动作、兔子轨迹和挂接时机使用同一份时间定义。

交付与验收：提供可烘焙动画、动作命名与事件说明、正面和侧面演示。整段正放与逐帧查看均连续；抓取、释放无位置跳变，双手接触可信，手指没有明显穿过兔子，抱持循环首尾一致。

## 第四阶段 接入 PocketWorld

接入前检查最新主分支、模型加载路径及正在进行的交互改动。重点核对 `ResidentModel.tsx`、`OrbitalResidents.tsx` 和 `useWorldController.ts` 的实际调用关系，并协调已有床铺交互工作，避免按旧版本直接覆盖实现。

模型加载改为使用 GLB 自带的骨架和蒙皮，停止对新模型调用旧的程序化重新绑骨逻辑。人物实例使用独立骨架与动画状态，避免共享缓存让多个角色相互影响。

世界交互逻辑负责决定何时抓取、抱持和放下，动画控制层负责姿势切换。角色位置、身体动画和裙骨动态分别确定唯一控制来源，避免逐帧代码与动画播放器同时修改同一根骨骼。

兔子在场景摆放与人物握持之间切换时，保持世界位置和朝向连续。需要时再增加少量手部接触修正，不预先引入复杂物理系统。

必须处理以下边界：抓取前取消，兔子保留原位；抓取后取消，进入稳定抱持或明确放置流程，不突然跳回起点。暂停恢复、快速重复点击和退出场景不能产生重复兔子、遗留挂接关系或僵住的人物。

交付与验收：游戏内抱兔全流程可重复执行，中断行为符合定义；原有移动、碰撞和已有交互不回退。完成桌面操作与模拟触屏检查，真机未测时单独标注。保留旧资产作为回退资源，未经明确要求不合并主分支或部署。

## 第五阶段 扩展正式动作与轻量动态

抱兔流程稳定后，依次制作坐下与起身、上床与起床、拿书与翻页。每次完成一个动作及其取消流程，再增加下一个。

入床按站稳、坐床沿、手撑床、抬腿、挪入、躺下分段制作。翻书明确手指接触、书页运动与阅读状态更新之间的关系，覆盖连续翻页和退出阅读。

最后加入裙摆和头发的惯性、阻尼及简化碰撞。先确定坐姿、卧姿下的基础裙形，再叠加动态。明确动画与动态系统的控制顺序，避免共同覆盖最终姿势；暂停恢复不能积累过大的模拟步长。

交付与验收：每个动作都有明确的开始、结束和中断姿势，常用视角下没有明显穿插，低帧率时不发散。性能先记录基线，再比较新增动画与动态的实际开销；不达标时优先减少动态骨链、碰撞数量及重复计算。

## 执行与完成边界

按第一至第五阶段顺序推进。按用户指定在 PR #23 的现有分支继续交付，记录成果、验证及未解决问题；PR #21 保留为初版资产的追溯入口。制作脚本不得覆盖后续人工精修成果。

第一批的完成条件是模型检查通过并交付 Blender 抱兔示范；完整方案的完成条件是游戏内交互、正式动作及动态效果各自通过验收。不能把结构验证通过等同于动作质量合格。

本方案不包含更换角色设计、重做整个世界控制器、默认引入重型布料引擎或给兔子增加独立角色行为。若现有几何无法达到验收标准，应明确需要局部重拓扑的部位、外观影响和工作量，再决定是否扩大修复范围。
